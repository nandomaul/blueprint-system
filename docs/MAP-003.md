# MAP-003 - Canvas rancangan yang memakai data nyata

## Pasang di Mac

1. Ctrl+C di Terminal dev lama. Root aktif `~/Desktop/0. Canvas UI-UX`.
2. Simpan `blueprint-map-003-patch.cjs` ke Downloads.
3. Terminal VS Code:

```bash
(
  set -e
  cd "$HOME/Desktop/0. Canvas UI-UX"
  node "$HOME/Downloads/blueprint-map-003-patch.cjs"
  npm ci --include=dev --bin-links=true
  npm run dev
)
```

Buka `http://127.0.0.1:5174`. Pertahankan hostname/port yang sama supaya data browser lama ditemukan. File CJS dijalankan di Terminal, bukan SQL Editor.

Patch memeriksa source SUPA-001 yang sesuai GitHub commit 60fca40, membuat backup di `~/Desktop/blueprint-checkpoints/MAP-003-...`, lalu menulis source. Bila source berbeda, patch berhenti sebelum menulis. Tidak menghentikan proses, menjalankan npm, push atau deploy.

## Pemakaian

- **Sistem baru**: nama sistem → satu halaman kosong. Pemilih Sistem membuka rancangan yang tersimpan secara terpisah.
- **+ Halaman**: halaman baru dalam sistem aktif. Nama dan route bisa diubah di baris atas. Duplikat menyalin komponen dan referensi dengan ID aset baru. Hapus halaman melepas koneksi, gambar dan tujuan tombol ke halaman tersebut.
- **Canvas**: tambah Judul/Teks/Tombol/Input/Kartu/Tabel/Gambar; klik komponen; ubah isi, posisi, ukuran, font, warna, radius. Drag memindahkan, sudut kanan bawah mengubah ukuran. Properti numerik juga bisa dipakai. Urutan layer menentukan komponen di depan. Undo/Redo berlaku selama sistem dibuka, maksimal 30 langkah.
- **Tombol → Jika diklik**: pilih halaman tujuan. Preview dan panah tab Alur membaca tujuan ini. Loop ke halaman sendiri diperbolehkan. Tombol tanpa tujuan memberi informasi di preview.
- **Gambar**: upload PNG/JPEG/WebP ≤4 MB, total aktif ≤20 MB, maksimal 30 gambar. Upload masuk referensi; **Pakai di canvas** menambah komponen gambar. **Hapus gambar** melepas referensi dan komponen dari rancangan aktif setelah konfirmasi. Snapshot History menyimpan gambar lama; file cloud tidak dihapus permanen karena masih dipakai riwayat.
- **Alur**: geser node/peta, zoom/fit, isi tujuan pengguna, output, PIC dan integrasi per halaman. Panah berasal dari tujuan tombol. Untuk menambah koneksi, tambahkan/atur tombol di Canvas.
- **Brief & data**: nama sistem, ringkasan, masalah, peran, ruang lingkup, keputusan, asumsi, struktur data, mapping Lark, acceptance dan pertanyaan. Urutan presentasi bisa diubah di bagian atas tab ini.
- **Preview**: desain yang sama dengan canvas; tombol berpindah halaman. Input hanya nilai uji sesi ini. **Presentasi / Demo** menambahkan panduan tujuan/hasil dan instruksi tombol; tersedia fullscreen. Ini belum menjalankan login HR, penyimpanan data bisnis, approval atau API Lark.
- **Autosave**: debounce 700 ms, satu antrean request per sistem. Draft perangkat dijurnal segera saat diedit. Gagal simpan ditampilkan sebagai gagal, dengan retry dan download draft. Refresh memulihkan draft yang belum terkirim.
- **History**: Simpan versi membuat checkpoint bernama. Autosave tidak membuat ratusan checkpoint. Buka hanya melihat; rename mengganti nama; hapus masuk Trash; pulihkan dari Trash; restore membuat checkpoint baru dari snapshot lama.
- **Download**: PDF handoff, JSON lengkap, impor JSON. Impor membuat sistem baru sehingga tidak menimpa sistem aktif.

## Online dan Realtime

Schema tambahan sudah dipasang pada `qjmwxezxtsuikywqoajj` melalui koneksi pengguna. Tidak perlu copy-paste SQL lagi untuk project ini. Salinan SQL untuk audit ada di `supabase/migrations/20261015072052_blueprint_canvas_documents.sql`. Jangan menjalankan migration awal lagi.

1. Satu orang: Settings → profil Nando/Hadist/Ryan → **Buat workspace** → **Buat & hubungkan**. URL dan publishable key sudah terisi.
2. Bila workspace masih kosong, sistem aktif perangkat disalin menjadi sistem pertama. Riwayat perangkat tetap tersedia melalui **Buka riwayat perangkat sebelumnya**. Ini bukan merge seluruh riwayat lokal ke cloud.
3. Owner: **Lihat undangan tim**. Ryan/Hadist buka Settings → **Gabung tim**, isi kode undangan yang sama. Pilihan N/H/R adalah label aktivitas, bukan verifikasi identitas.
4. Setelah koneksi: status simpan harus **Tersimpan ke Supabase**, status websocket harus **Realtime terhubung**. Keduanya terpisah. Bila Realtime reconnect, refetch berkala 15 detik dan saat tab fokus/online tetap berjalan.
5. Tab bersih menerima rancangan baru dari tim. Bila ada perubahan lokal pada saat dokumen yang sama diperbarui orang lain, aplikasi menahan draft dan memberi konflik. Download draft sebelum **Muat versi tim**. Tidak ada penggabungan CRDT per komponen; pengguna menyelesaikan konflik dokumen secara eksplisit.

Database memakai membership workspace + RLS, RPC bertransaksi dan token optimistic concurrency. Storage privat memakai hash isi dan upload immutable. Kode undangan memberikan akses edit; simpan sendiri, jangan commit. Tidak ada secret/service-role key dalam frontend.

## Isi PDF handoff

- Identitas dan ringkasan sistem, brief, keputusan vs asumsi, data model dan mapping integrasi.
- Visual semua halaman, ID/route, tujuan/output/PIC, spesifikasi komponen, tujuan tombol dan koneksi.
- Referensi gambar beserta halaman, versi, penulis, waktu; urutan presentasi dan bagian yang belum lengkap.
- Instruksi chat berikutnya dan batas prototype.
- Attachment `blueprint.json` dan `handoff.md`; download JSON terpisah juga tersedia karena pembaca PDF/chat tidak selalu membuka attachment.

PDF dibuat langsung sebagai file, bukan dialog print. WebP dikonversi ke PNG untuk PDF. Font DejaVu Sans disertakan dengan lisensi. Karakter yang tidak didukung font menyebabkan pesan jelas; gunakan JSON lengkap atau ubah karakter tersebut, bukan menghasilkan glyph rusak. PDF adalah snapshot visual berskala; ukuran, layer, radius dan seluruh data asli dipertahankan di JSON.

## Verifikasi dan batas

Typecheck, lint, 26 tes Node (termasuk PGlite PostgreSQL, IndexedDB, HTTP mock dengan SDK Supabase asli, PDF), dan skenario UI dalam JSDOM. UI DOM memeriksa membuat sistem/halaman, edit visual, navigasi tombol, upload/hapus gambar, autosave reload, profil, rename/Trash/untrash/restore History, download JSON/PDF. Image decoder di DOM distub karena JSDOM tidak menyediakan decoder raster.

PDF aktual dirender dengan Poppler dan diperiksa tata letaknya; JSON attachment dibuka kembali. Build lokal/portable dan base GitHub Pages diverifikasi. JSDOM bukan browser QA; drag pixel, fullscreen native dan sinkronisasi dua browser/perangkat belum diklaim terverifikasi.

Remote: migration additive sudah diterapkan; kedua tabel dipublikasikan ke `supabase_realtime`; RLS aktif. Save, checkpoint, konflik, rename/Trash/untrash dan penolakan outsider diuji dalam transaksi rollback. Tidak ada user/workspace uji tertinggal. Storage cloud + perubahan dua perangkat belum diuji dari browser pengguna. Advisor menandai anonymous Auth dan RPC security-definer yang memang dipakai; akses tetap mensyaratkan membership, helper search_path kosong, anon tanpa sesi tidak mendapat EXECUTE.

## GitHub Pages dan rollback

Source di laptop/Pages tidak berubah sebelum patch dijalankan. Setelah dev diperiksa, publikasi mengikuti `docs/GITHUB-PAGES.md`: hentikan dev, `node scripts/push-github.cjs`, lalu GitHub Actions → Publish Blueprint to GitHub Pages → Run workflow branch main. Jangan gunakan build portable sebagai artifact Pages; workflow memakai base `/blueprint-system/`.

Rollback source: hentikan dev, jalankan perintah `node ".../rollback.cjs"` yang dicetak patch; lalu `npm ci --include=dev --bin-links=true` dan `npm run dev`. Backup menolak rollback bila file berubah lagi. Database browser lama v1 dipertahankan; rancangan MAP-003 ada di database terpisah dan tidak dihapus rollback. Export JSON sebelum rollback untuk membawa perubahan terbaru. Cloud migration additive tidak dihapus; frontend lama melihat snapshot lama, bukan rancangan MAP-003 terbaru. Tidak ada rollback SQL destruktif otomatis.
