Status: source revisi dibuat dan diperiksa pada Linux/Node 24; belum diterapkan di laptop, belum deploy. Cloud adapter dan SQL tersedia; tenant Supabase pengguna belum tersambung atau diubah.

## Pasang satu patch di VS Code

Root laptop yang dipakai: `~/Desktop/0. Canvas UI-UX`. Jika folder masih bernama `0. Canvas UI:UX`, ganti namanya menjadi `0. Canvas UI-UX` dulu, lalu buka ulang folder itu lewat File → Open Folder di VS Code. Tanda `:` pada path memecah PATH executable npm, penyebab error Vite sebelumnya. Jangan membuat proyek baru lagi.

1. Pada aplikasi lama klik **Simpan versi**, lalu **Ekspor** untuk backup data peta. Data browser terpisah dari source.
2. Download `blueprint-map-002-patch.cjs` ke `~/Downloads` dengan nama persis itu.
3. Di Terminal yang menjalankan dev, tekan **Ctrl+C** sampai prompt kembali.
4. Buka root yang benar di VS Code → Terminal → New Terminal. Tempel satu blok ini:

```bash
(
  set -e
  cd "$HOME/Desktop/0. Canvas UI-UX"
  node "$HOME/Downloads/blueprint-map-002-patch.cjs"
  npm ci --include=dev --bin-links=true
  npm run dev
)
```

5. Buka **http://127.0.0.1:5174** dengan browser/profil yang sebelumnya dipakai. Tetap gunakan alamat itu; `localhost` memiliki penyimpanan berbeda.
6. Refresh halaman. Pada strip proyek harus tertulis **MAP-002**. Tidak perlu menimpa file satu per satu.

Patch memeriksa source MAP-001 sebelum menulis, berhenti jika ada perubahan yang tidak dikenal, serta membuat backup di luar root dan script rollback. Tidak menghentikan proses, menjalankan npm, menimpa .env, mengubah IndexedDB, mengirim SQL, atau deploy. Dependency tambahan dipasang secara eksplisit lewat npm ci: Supabase SDK untuk koneksi dan PGlite sebagai alat uji SQL. Versi toolchain lainnya dipertahankan.

Jika port 5174 masih terpakai, hentikan server terkait dengan Ctrl+C pada Terminal lamanya. Jangan kill semua proses Node. Jika hash source berbeda, jangan paksa: kirim source terbaru supaya patch dibuat sesuai file aktual.

## Menyalakan simpan online — satu kali untuk tim

Adapter siap dipakai; langkah ini perlu akun/project Supabase yang benar. Tidak perlu mengirim secret key ke chat. Untuk project existing, periksa schema dan policies melalui Dashboard dulu. Migration hanya menambah nama `bp_*` dan bucket baru; jika nama sudah ada, seluruh transaksi berhenti sehingga perlu diperiksa, bukan dihapus/dipaksa ulang.

1. Buka project Supabase yang ditujukan untuk **workspace perancangan**, bukan otomatis database produksi HR.
2. **SQL Editor → New query**. Di VS Code buka:
   `supabase/migrations/202610150001_blueprint_workspace.sql`
   relatif terhadap root `~/Desktop/0. Canvas UI-UX`.
3. Agar tidak menyalin manual dari editor, jalankan di Terminal macOS:

   ```bash
   pbcopy < "$HOME/Desktop/0. Canvas UI-UX/supabase/migrations/202610150001_blueprint_workspace.sql"
   ```

   Lalu Cmd+V di SQL Editor dan **Run** sekali. Hasilnya enam tabel `bp_*`, RPC simpan/history, RLS membership, dan private bucket `blueprint-designs`. Jangan menjalankan migration pada project yang belum diperiksa. Jangan menyalin service_role/secret ke aplikasi.
4. Supabase Dashboard → **Authentication → Sign In / Providers → Anonymous Sign-Ins** → aktifkan. Nama menu Dashboard dapat berubah; fitur yang dicari adalah anonymous sign-ins. Pengguna mendapat sesi Auth tanpa email/password.
5. **Project Settings → API / API Keys**: ambil Project URL dan **publishable key** (`sb_publishable_…`; legacy anon key juga didukung). Keduanya boleh untuk frontend; secret/service_role tidak didukung.
6. Pada aplikasi → **Settings** → isi URL dan publishable key → pilih **Buat workspace** → **Buat & hubungkan**. Cukup satu orang membuat workspace tim.
7. Workspace baru kosong: peta yang sedang ditampilkan tetap ada. Klik **Simpan versi**, beri nama. Tunggu pesan **Versi dan gambar tersimpan di Supabase**. Tidak ada overwrite peta tim otomatis saat koneksi pertama.
8. Di Settings pembuat workspace, simpan **ID workspace** dan **kode undangan**. Tombol **Lihat undangan tim** menampilkan kembali kode bagi pembuat. Jika respons pembuatan terputus, pilih Buat workspace lagi pada sesi yang sama; RPC mengembalikan workspace milik sesi itu.
9. Ryan/Hadist menjalankan source ini di perangkat masing-masing → Settings → pilih profilnya → URL/key yang sama → **Gabung tim** → masukkan kode undangan → hubungkan. Jika sudah ada peta tim, aplikasi meminta konfirmasi dan memulai ekspor peta yang tadinya tampil sebelum beralih. Pastikan file ekspor masuk Downloads.
10. Cek silang: Nando simpan → Ryan refresh → versi dan gambar yang sama muncul → Ryan rename/save → Nando refresh. Bila dua anggota menyimpan dari token lama, anggota kedua mendapat konflik; ekspor perubahannya dulu, muat ulang, lalu rekonsiliasi.

Tidak ada realtime editing pada revisi ini. Refresh untuk mengambil perubahan anggota lain. Saat cloud aktif, jaringan gagal menghasilkan pesan gagal; aplikasi tidak mengklaim sukses atau diam-diam menulis ke perangkat sebagai pengganti cloud.

Riwayat perangkat MAP-001 tetap tersimpan. Untuk membukanya: Settings → **Buka riwayat perangkat sebelumnya**. Tindakan ini menonaktifkan pilihan cloud di browser tersebut sampai disambungkan kembali. Checkpoint lama tidak diunggah massal; buka/restore snapshot yang diperlukan, hubungkan workspace kosong atau impor secara eksplisit, lalu simpan versi baru. Ekspor JSON membawa peta aktif beserta gambar, bukan seluruh daftar History.

Sesi anonymous disimpan browser. Jika data situs terhapus atau pindah perangkat, pilih Gabung tim lagi menggunakan kode. Profil N/H/R boleh diganti, bukan tiga akun terverifikasi dengan pemulihan akun. Simpan ID/kode undangan dengan tim. Aturan Storage tidak menyediakan overwrite atau delete; file yang tidak lagi dipakai akan tetap ada untuk menjaga pemulihan versi. Pengelolaan kuota/retensi berikutnya perlu desain tersendiri.

Supabase hanya untuk workspace Blueprint. Sistem HR tetap menargetkan Feishu People sebagai master dan Lark Base/workflow untuk operasional. Login HR, data contoh dan persetujuan dalam preview tetap simulasi.

## Rollback source

Patch mencetak lokasi backup dan perintah rollback yang tepat, misalnya:

```bash
node "$HOME/Desktop/blueprint-checkpoints/MAP-002-TIMESTAMP/rollback.cjs"
```

Hentikan dev dahulu. Gunakan path sebenarnya yang dicetak, bukan kata TIMESTAMP. Lalu dari root jalankan `npm ci --include=dev --bin-links=true` dan `npm run dev`. Rollback memeriksa hash agar tidak menimpa revisi source setelah patch. Source/data browser/database merupakan hal terpisah: rollback source tidak memutar balik database atau checkpoint data.
