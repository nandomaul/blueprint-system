# MAP-014 — Kolaborasi dan interaksi canvas

## Hasil

- Isi proyek, perubahan komponen/halaman/koneksi, gambar, metadata proyek, Trash, History dan chat memakai repository Supabase yang sama. Perubahan dikirim otomatis setelah berhenti mengedit sebentar; status Tersimpan hanya setelah konfirmasi server. UI bukan stream setiap ketukan; latensi mengikuti jaringan dan server.
- Maksimal3 avatar editor di kiri ikon Preview; sisanya +N. Klik avatar untuk melihat proyek, halaman, tampilan dan aktivitas. Klik orang untuk membuka lokasi rancangan itu. Profil yang sama pada beberapa sesi dikelompokkan, dengan jumlah sesi di daftar. Nama/foto profil tetap label bersama, bukan identitas yang diverifikasi.
- Presence bersifat sementara: keluar/putus koneksi menghapus kehadiran setelah server mendeteksi disconnect. Lokasi dan status tidak mengubah rancangan atau viewport anggota lain.
- Klik background User Flow melepas highlight/popup koneksi dan mode sambung. Geser2jari touchpad untuk pan dua arah; Ctrl/Meta+wheel atau pinch yang dilaporkan browser tetap zoom. System UI dan Design UI memakai scroll/pan yang sama. Tidak mengubah zoom browser/menu Safari.
- Trash proyek langsung dari menu atau bulk manager, tanpa ketik kode. Halaman/gambar/komponen tetap soft-trash dan bisa dipulihkan. Server RPC lama dipertahankan untuk kompatibilitas; UI mengirim konfirmasi protokolnya otomatis.
- Menu tiga titik memakai posisi mengikuti batas viewport dan baris ringkas, tanpa scroll internal pada ukuran layar normal.

## 1. SQL tambahan yang perlu dipasang

File `blueprint-shared-MAP-014.sql` adalah **SQL murni**. Memerlukan schema Blueprint MAP-012 yang sudah terpasang. Tidak reset dokumen/History/chat/gambar. Bisa diulang; pilihan ruang utama yang sudah ada dipertahankan.

Pemasangan lewat koneksi MCP belum berhasil: versi akses terbuka ditolak auto-review; versi aman anggota-saja berikutnya mengembalikan `Invalid or expired requestState`. Read-only recheck memastikan migration belum terpasang. File yang dikirim adalah **versi aman**, bukan versi akses terbuka yang ditolak.

Simpan SQL di Downloads, lalu:

```bash
pbcopy < "$HOME/Downloads/blueprint-shared-MAP-014.sql"
open "https://supabase.com/dashboard/project/qjmwxezxtsuikywqoajj/sql/new"
```

Di **SQL Editor → New query**, Cmd+V → **Run**. Jangan paste file `.cjs` di SQL Editor. SQL juga ada di `supabase/manual/blueprint-shared-MAP-014.sql` setelah installer dipasang.

SQL menambah pemetaan ruang utama dan aturan Presence khusus anggota. Di project ini ruang pertama adalah `1e6615c9-4f88-4ebc-a448-5e4226d2d459`. Konfirmasi setelah Run:

```sql
select s.workspace_id,w.name
from blueprint_private.shared_entry s
join public.bp_workspaces w on w.id=s.workspace_id;
select policyname from pg_policies
where schemaname='realtime' and tablename='messages'
and policyname in ('bp_presence_read','bp_presence_track');
```

Hasil pertama harus ruang utama dan query kedua menghasilkan2 policy. Bila Run error, hentikan dan kirim error utuh; jangan reset tabel.

## 2. Pasang source di Mac

Simpan `blueprint-map-014-patch.cjs` di Downloads. Terminal VS Code:

```bash
(
  set -e
  cd "$HOME/Desktop/0. Canvas UI-UX"
  node "$HOME/Downloads/blueprint-map-014-patch.cjs" --stop-dev
  npm ci --include=dev --bin-links=true
  npm run dev -- --open '/'
)
```

Seluruh file masuk otomatis ke root Canvas. Backup di `~/Desktop/blueprint-checkpoints/MAP-014-...` dan perintah rollback dicetak. Installer menolak source yang tidak sesuai baseline; jangan paksa overwrite. Alias lokal `scripts.deploy = npm run build` dipertahankan. `--stop-dev` hanya menghentikan Vite5174 dari root ini yang terverifikasi. Rollback source tidak menghapus SQL/data.

## 3. Masuk dan samakan ruang

Pilih nama atau buat profil baru lalu **Masuk**. Anggota yang sudah punya izin ke ruang utama tidak mengisi kode. Perangkat baru masih perlu membuka undangan tim sekali; itu memberi sesi browser izin menjadi anggota. Link undangan lama tetap bekerja dan boleh dibuka di tab baru, tanpa mengetik kode.

**Akses terbuka belum diaktifkan.** Permintaan agar semua pengunjung otomatis menjadi editor ruang utama ditolak auto-review karena memperluas akses produksi tanpa verifikasi. Persetujuan eksplisit pengguna diperlukan untuk perilaku tersebut. Jangan menyelipkan kode undangan ke frontend atau melepas RLS untuk mengakali penolakan.

Localhost dan website mempunyai sesi browser terpisah. Keduanya perlu izin ke ruang utama yang sama; setelah itu isi proyek sama dan realtime. Perubahan kode source baru muncul di website setelah deploy, sedangkan edit isi proyek tidak perlu deploy. Zoom/pan/seleksi/posisi panel/bahasa tetap preferensi per perangkat.

Proyek di ruang lain tidak dihapus/ditimpa. Jika membutuhkan salinan di ruang utama, ekspor JSON dari ruang asal lalu impor sebagai proyek baru; jangan menimpa dokumen dengan ID sama lintas ruang.

## Verifikasi dan batas

64 tes Node/domain/SQL, UI DOM, typecheck/lint/build dan build Pages lolos. Uji Supabase asli memakai2 sesi independen dalam workspace QA terpisah: penghapusan beberapa komponen diterima sesi lain, Trash/restore tersimpan, chat push + mention + konteks halaman/design + read cursor berhasil. Presence diuji service/DOM/PGlite dengan isolasi membership/topic; belum diverifikasi online karena SQL tambahan belum terpasang. Tidak mengklaim screenshot native Safari/HP.

Advisors pada database yang belum diubah melaporkan fungsi fondasi SECURITY DEFINER dan kebijakan anonymous-member yang perlu ditinjau untuk hardening tersendiri; bukan hasil audit keamanan bersih. Referensi: [fungsi SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [anonymous access](https://supabase.com/docs/guides/database/database-advisors?queryGroups=lint&lint=0012_auth_allow_anonymous_sign_ins), [RLS tanpa policy](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy). Tabel invite/visitor yang tanpa policy memang tertutup untuk client; jangan memberi policy semua-boleh agar INFO hilang.
