# MAP-004 — Ruang tim dan editor canvas

Revisi ini melanjutkan tool perancangan Personnel. Aplikasi HR/Lark sebenarnya tetap proyek berikutnya. Frontend belum dipush atau diterbitkan dari lingkungan ini.

## Pasang tanpa menimpa file satu-satu

Patch kumulatif menerima source SUPA-001 (GitHub main 60fca40 saat diperiksa) atau MAP-003 yang identik dengan paket sebelumnya. Tidak perlu memasang MAP-003 dahulu. Source yang telah diedit dan tidak cocok akan ditolak sebelum penulisan, bukan dipaksa.

1. Simpan `blueprint-map-004-patch.cjs` di **Downloads**.
2. Pada Terminal yang menjalankan dev, tekan **Ctrl+C**. Patch tidak menghentikan proses sendiri.
3. Buka root `Desktop/0. Canvas UI-UX` di VS Code, lalu tempel seluruh blok:

```bash
(
  set -e
  cd "$HOME/Desktop/0. Canvas UI-UX"
  node "$HOME/Downloads/blueprint-map-004-patch.cjs"
  npm ci --include=dev --bin-links=true
  npm run dev
)
```

4. Buka **http://127.0.0.1:5174**, muat ulang, dan pastikan tertulis **MAP-004**. Pakai browser/profil dan alamat yang sama seperti sebelumnya untuk menemukan data perangkat lama. `localhost`, `127.0.0.1`, Pages dan file HTML memiliki penyimpanan browser terpisah.
5. Jika root masih `0. Canvas UI:UX`, ubah namanya di Finder menjadi `0. Canvas UI-UX`, lalu buka ulang di VS Code. Tanda titik dua memecah PATH npm pada macOS dan dapat menyebabkan `vite: command not found` meskipun dependency terpasang.

Node 24.x diperlukan. `--include=dev --bin-links=true` memasang Vite dan symlink bin lokal. Installer tidak menjalankan npm, SQL, push atau deploy. Bila source ditolak, simpan pesan error dan kirim source terbaru; jangan menghapus guard atau menghapus proyek.

## Menghubungkan dua laptop dengan benar

N/H/R adalah nama editor, bukan akun lintas perangkat. Akses memakai sesi Supabase tanpa password dan keanggotaan ruang melalui undangan.

**Laptop pertama:** pilih nama → **Buat ruang tim** → beri nama. Bila data lama ditemukan, centang **Salin proyek perangkat ini** untuk mengunggah rancangan aktif beserta gambar ke ruang tersebut. Data asal dan History lama tetap di perangkat. Sesudah masuk, gunakan **Ruang tim** pada beranda, atau **Bagikan** di editor → **Salin tautan undangan**.

**Laptop kedua:** pasang revisi MAP-004 juga. Buka dev lokal di laptop itu, pilih **Gabung tim**, lalu paste tautan/kode dari laptop pertama. Tautan localhost membuka server laptop masing-masing, bukan server laptop pertama. Pada kedua laptop, **Profil & ruang tim** harus menampilkan **ID yang persis sama**. Buka proyek yang sama dari beranda.

Bila pernah terhubung ke ruang berbeda, buka **Profil & ruang tim → Ganti ruang tim**, kemudian gabung dengan undangan yang benar. Kegagalan menyambung ditampilkan sebagai error; aplikasi tidak diam-diam mengalihkan penyimpanan ke perangkat.

Undangan memberikan hak edit ruang kepada pemegangnya. Bagikan hanya ke tim. Session browser tetap perlu dijaga; menghapus data situs menghapus session perangkat, sehingga perlu gabung kembali memakai undangan. Sesi ini bukan identitas perusahaan atau akun HR terverifikasi.

## Autosave dan kerja bersama

Perubahan dikirim setelah jeda sekitar 0,5 detik. Supabase Postgres Changes memperbarui daftar proyek, rancangan aktif dan History yang sedang dibuka. Status Live muncul setelah sinyal database-ready, bukan hanya ketika tab dibuka. Refresh saat focus/online dan polling 15 detik menjadi cadangan saat koneksi Realtime terganggu.

Server memakai lock transaksi per proyek dan merge tiga arah terhadap versi dasar. Edit pada objek berbeda, serta properti berbeda pada objek yang sama, dapat digabung. Mengubah teks yang sama bersamaan, menghapus objek yang sedang diedit, atau menghasilkan relasi/ukuran yang tidak valid menimbulkan konflik. Urutan layer yang sama-sama diubah secara berbeda juga ditahan. Ini bukan character-level CRDT atau cursor/presence bersama.

Draft yang belum terkirim disimpan di IndexedDB. Saat konflik, unduh draft JSON sebelum memilih muat versi tim. Draft tidak dianggap berhasil tersimpan online. Undo direset saat perubahan tim digabung agar snapshot Undo lama tidak mengembalikan perubahan tim secara diam-diam.

Pemulihan awal mengunggah rancangan aktif/draft dan membuat checkpoint pemulihan, bukan memalsukan waktu serta penulis History lama sebagai waktu cloud. Riwayat asal masih dapat diperiksa lewat Data perangkat. Proyek historis dengan ID berbeda juga ditampilkan agar tidak tersembunyi setelah impor lama.

## Verifikasi dan batasnya

- Node 24/Linux: TypeScript strict, lint, 32 tes domain/persistence/SQL/SDK/PDF, skenario interaksi UI JSDOM, build dev/portable dan base Pages.
- Dua sesi repository/autosaver diuji dengan perubahan bersamaan, konflik dan reload. Transport SDK Supabase diuji dengan HTTP mock; SQL merge diuji terpisah pada PostgreSQL PGlite.
- Database Supabase project `qjmwxezxtsuikywqoajj`: migrasi diterapkan; merge dua anggota, same-field conflict, checkpoint dan penolakan outsider diverifikasi dalam transaksi rollback. Fixture user/ruang/proyek tidak ditinggalkan.
- Advisor masih menandai anonymous signed-in membership dan RPC SECURITY DEFINER yang sengaja menjadi API terbatas anggota. RPC memeriksa `auth.uid()`/membership, search_path kosong, helper merge tidak diekspos, dan anon tanpa sesi tidak bisa menulis. `bp_invites` sengaja tidak memiliki kebijakan baca langsung; akses lewat RPC owner/join. Panduan advisor: https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable dan https://supabase.com/docs/guides/database/database-advisors?queryGroups=lint&lint=0012_auth_allow_anonymous_sign_ins.
- Browser pengujian gagal terbuka karena timeout; tidak ada klaim visual QA browser atau dua laptop fisik. Drag/resize, layout Safari/mobile, clipboard undangan, websocket lintas perangkat dan fullscreen native masih perlu dilihat di browser pengguna.
- Build menandai bundle besar karena font/PDF handoff terbundel. Belum dibuat code splitting/caching lintas halaman. Tidak ada avatar “online” atau koneksi Lark/WeChat palsu.
- Source belum diterapkan di Mac pengguna, belum user accepted, dan frontend belum dipush/deploy. Pages yang lama tetap lama sampai publikasi diminta.

## Backup dan rollback

Installer memeriksa seluruh source yang dikenal, membuat backup di `~/Desktop/blueprint-checkpoints/MAP-004-...`, men-stage file, lalu menulis atomik. Perintah rollback lengkap dicetak di Terminal. Jika penulisan gagal, file yang sudah diubah dikembalikan otomatis.

Untuk rollback source, hentikan dev dengan Ctrl+C, jalankan `node "/path/backup-yang-dicetak/rollback.cjs"`, lalu `npm ci --include=dev --bin-links=true` dan `npm run dev`. Rollback menolak source yang sudah diedit setelah patch agar pekerjaan baru tidak hilang. Data browser dan Supabase tetap tersedia; fungsi database tambahan tidak perlu dihapus untuk rollback source.
